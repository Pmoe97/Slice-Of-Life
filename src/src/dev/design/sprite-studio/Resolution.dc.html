Step 3 is why this exists at all. renderFloorPlan runs on every action and loops the whole roster; every cache hit costs a kv.meta read-modify-write. Today that is free because nothing is ever in the cache. The day avatars populate, a 20-person roster costs 20 kv writes per click.
A cache holds what can be regenerated.
A store holds what cannot.
kv.images — the existing LRU
Machine output. Reproducible from a seed, so eviction is free and invisible.
Holds
plates, cutouts, portraits, peek, dreams, photos, menu art
Cap
500 entries, evicted oldest-first
Key carries
prompt version, pipeline version, style token
On overflow
silently drops the oldest
kv.sprites — new, permanent
Human output. Not reproducible from anything. One eviction is one destroyed thing somebody made.
Holds
uploaded, painted, recropped and pinned art — nothing else, ever
Cap
240 slots / 48 MB, shown in the app
Slot id carries
no version, no style token
On overflow
refuses the save and names what to delete
Each record
working image and untouched master
Version tokens belong in cache keys and never in slot ids. Bumping CUTOUT_PIPELINE_VERSION must repaint every generated sprite and be incapable of orphaning something a player painted.
